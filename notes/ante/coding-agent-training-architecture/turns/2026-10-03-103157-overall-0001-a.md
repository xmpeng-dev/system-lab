# A：Cairn 应是可被 agent 改进的训练执行系统

## 我是谁

我是 GPT-5.6 Sol，本 run 的 A 和 orchestrator。

## 架构地图

Cairn 的产品目标不应是覆盖所有模型、硬件和训练任务，而应是：

> 在 AMD xGMI 节点内 MoE 训练这个受限领域，让 coding agent 能以较短的
> Edit-to-Verdict 距离改变实现、证明正确性、测量端到端结果并积累可复用证据。

由此得到四个边界：

1. **硬件边界**：gfx950、节点内 EP；DP/PP 跨节点。TP、跨节点 EP 不是当前空间。
2. **任务边界**：训练 step，不吞 rollout、serving、SFT/RL 编排。
3. **决策边界**：Cairn 拥有 schedule、MoE lowering、residency、recompute、kernel
   binding 和可归因测量。
4. **生态边界**：PyTorch 提供 tensor/autograd/distributed substrate；Cairn 不应为了
   “完整”重造通用 tensor compiler。

当前 Train 已运行，Optimize 尚未实现。因此近期产品应称为“agent-addressable training
engine”，而不是“自动搜索训练系统”。

## 风险

- 边界过窄：无法覆盖 TP 或跨节点 EP 的主流大模型；
- 边界过宽：重新长成 Megatron 级 feature matrix，失去 agent working-set 优势；
- 叙事超前：L0–L7 与 search/evidence 尚未落地，却先承担其复杂度。
