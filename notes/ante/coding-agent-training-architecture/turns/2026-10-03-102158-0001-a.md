### 判断

第 1 类为空，我让步：未来两个 milestone 里，没有已排期的变换必须看到 lowering 之前的
primitive MathGraph。

但证据支持另一个结论：**lowering 之后的 typed task 粒度**是已排期、已测量的真实需求。
`hands_over` 与 `defer_metadata_waits` 依据 task 输出的 dtype 和 host-read 声明做决定；
`FusedMoE` 的 −9.5% 是隐藏这一粒度的实测代价。因此 RegionGraph 只有在以下条件下才等价：
region lowering 发出带 `TensorSpec` 与 effect 的 collective/compute task，verifier 继续在这一层
运行。

### 待验证假设

- H1：RegionGraph 前端若在 MoE region 内发出相同 task 序列，其 Program digest 应与当前
  `DynamicAllToAll` 一致——可在 CPU 上用 `tests/contracts` 比较 digest 验证。
- H2：跨层 residual-norm 融合在 DSV3 宽度有端到端收益——目前只有 `bench/kernels.json` 的
  微基准，没有 run 级数字。
