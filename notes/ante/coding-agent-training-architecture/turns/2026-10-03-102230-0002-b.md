### 通过标准的草图（约 10 行）

Qwen3 今日：`Add`@`ATTENTION` → `RMSNorm`@`ROUTER` → route（含 load-balance effects）→ MoE 仍吃 `residual`。

Region 切分不改 Round 1 名字，只把**残差+norm 收成边界 custom-op**，由 **Attention 的 implementation 选择**是否启用融合体（DeepSeek 已在模型侧直接发 `ResidualRMSNorm`，同一端口）：

```text
Attention
  in:  x
  out: attn_delta                    # 仅 attention 增量，不是 residual
  impl: PyTorch / owned attn ops

ResidualRMSNorm                      # 边界 custom-op；非 Router 数学
  in:  x, attn_delta
  out: normed, residual              # 谁“拥有”：boundary op，不属于 Router effects
  choice: fused Triton | Add+RMSNorm  # 取代全图 FuseResidualNorm walk

Router
  in:  normed
  out: idx, weight, scores
  effects: LoadBalanceLoss 仍只在此   # 不挪走

RoutedExperts
  in:  normed, residual, idx, weight
```

要点：

1. **不做**全图 `Add`→`RMSNorm` 遍历：融合是 `ResidualRMSNorm` 这一 port 的 implementation / kernel choice，写入 `Implementation` / `run.json`，与今日 `fusions` 字段同层，不必看见 `Reshape`/`Linear`。
2. **不挪走** load-balance：effects 仍挂在 Router；norm 无跨 region 调度效应。
3. 若坚持 Round 1 字面把 post-attn norm 画进 `Router`：等价写法是 Router 的**第一个** port 就是 `ResidualRMSNorm`（DeepSeek 已把该 op 放在 `Block.ROUTER`），Attention 只出 `attn_delta`。仍无全局 pattern matcher。
4. 失败条件不成立：我没有把 Attention 扩到“内部再长一套 fine graph”；boundary 是一个已存在的算子（`ResidualRMSNorm`），不是嵌入 MathGraph。

因此 A 举出的“最近 primitive 候选”落在我的第 3 类：它约束的是 **region 切在哪**，不是 **必须拥有 Add/RMSNorm 作为独立 IR 节点**。
