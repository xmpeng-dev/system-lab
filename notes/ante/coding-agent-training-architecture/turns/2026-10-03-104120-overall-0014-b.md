# B：P5 — 梯度门禁是真的；笛卡尔积不是自动 CI 全绿证明

## 发言

### 门禁是什么

`test_engine.py`：同一模型建两遍——按名读参的独立 torch reference，与 FSDP×PP×EP 下编译 Program——比较 **loss 与每个梯度**。CLI 可选 `--schedule`、`--moe`、`--expert-parallel`、`--capacity-factor`。PP 另有 `test_pipeline_parallel.py`（含 `--scheduler dualpipe_v`）。

### 已练习的覆盖（AGENTS / 近期 GPU suite，非“每个组合每 commit”）

| 维度 | 已跑过的点 |
|---|---|
| MoE | dynamic / static / fused（含 ep=1 与 ep=8 若干） |
| schedule | single、single_overlap、one_f_one_b、interleaved、dualpipe_v（pp=2；dualpipe 另有 pp2×ep4） |
| 合同层 | `tests/contracts`：IR/compiler/schedule/record/verifier CPU |

### 明确缺口 / 不证明

1. **不是** 5 schedulers × 3 MoE × 所有 mesh 的自动矩阵每个 PR 全跑。
2. **不证明** tok/s、显存峰值、floor（那是 `check_regression` + 真机 run）。
3. Static capacity&lt;ep 时 **有意** 与 dynamic 非梯度相同（丢弃）；测试在 capacity=ep 对齐。
4. `AutogradVjp` 出货绑定为空；门禁假设显式 VJP。
5. 数值在 bf16 噪声内：跳过余弦等——tolerance 来自 Recipe。
