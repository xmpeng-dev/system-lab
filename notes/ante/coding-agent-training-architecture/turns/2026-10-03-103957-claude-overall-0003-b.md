# B：verifier 管住了静态维度和 effect 的「顺序」，没管住动态维度和 effect 的「完整性」——收窄原命题

## 我是谁

我是 B（Architecture Advocate），由 Claude orchestrator 启动的 general-purpose subagent。本 turn 不改仓库，
只在 `xiaoming-dev` 容器里跑了一个 CPU 探针（脚本 `/tmp/bprobe/sym.py`）。

## 我回应的命题

C 在 turn 2 的命题：`TensorSpec`/`Sym` 与 `effects()` 足以在分配前拦住错误。C 要攻击三点：Sym 按名字
判等、effect 声明的完整性靠什么保证、有没有 effect 表达不了的约束。

## 发言

### 事实

1. **第 1 点：Sym 判等确实放过错误程序（CPU 实测）。** `Sym` 是 `frozen dataclass(name: str)`
   （`spec.py:19-23`），`same_dims` 用 `==`（`spec.py:134`）。动态维度的名字都是固定字符串，与
   layer 和 micro-batch 无关：`AllToAll.infer` 的 `Sym("a2a_"+what)`（`ops.py:600`）、`Sym("recv_rows")`
   （`:617`）、`Sym("sorted_rows")`（`:635`）。我用 `GraphBuilder` 手写两层 dispatch，探针结果：
   - 两层 `AllToAll(...,"tokens")` 的输出 spec 都是 `bfloat16[?a2a_tokens,16]`，`equal: True`；
   - `Add(第 0 层行, 第 1 层行)` 被 **ACCEPTED**；
   - `ExpertSiluMul(?sorted_rows, ?a2a_tokens_back)` 被 **ACCEPTED**——它只比较宽度
     （`ops.py:679-681`），不比较行数，也不检查 `up` 的 layout；
   - 整图 `verify_graph` **PASSED**。

   `tests/contracts` 中没有任何测试引用 `Sym`、`sorted_rows` 或 `recv_rows`。
2. **第 2 点：缺口是 review 抓到的，不是测试。** 结构根源是 `Op.backward_effects()` 的默认实现
   `effects() if self.collective else ()`（`ops.py:60-61`）：`FusedRoutedExperts.collective` 为 False，
   修复前它的反向默认声明为「无 effect」，实际却发出两次 all-to-all。修复是覆写 `backward_effects`
   （`ops.py:823-828`），并新增 `test_the_fused_backward_declares_the_collective_it_issues`
   （`test_compiler.py:499`）。这个测试只断言这一个 op。除它和 `test_compiler.py:538/552` 两处篡改
   测试外，没有测试核对「声明的 effect」与「实现实际发出的东西」是否一致。
3. **第 3 点：有些约束只写在 docstring 里，effect 表达不了：**
   - `AllToAll` 输出有 padding，只有前 `sum(splits)` 行是数据（`ops.py:587-589`）；
   - `ExpertSort` 只读 `tokens` 的前 `len(expert_idx)` 行（`:624-625`）；
   - grouped GEMM 写到 offs 之后的部分是垃圾（AGENTS.md Testing Gotchas）；
   - StaticCapacity 超出容量的部分被丢弃；
   - `HostSync` 不参与 `_effect_order` 的排序（`verify.py:137-143` 的 `else: continue`），这是有意的
     （docstring：「a host read may move past a collective」）；
   - stream / HW queue 占用没有任何 effect 类型可以表达。

### 判断

- **原命题过宽，我收窄它。** verifier 确实能在分配前拦住：
  - 静态 shape 错误；
  - 使用先于定义；
  - composite 残留；
  - balance loss 被读两次；
  - 有 effect 的节点被 recompute；
  - 同一资源上的 collective 乱序；
  - P2P 通道顺序错误与死锁（`test_ir.py:69-219`、`verify.py` docstring）。

  但它拦不住动态维度的来源混淆，也拦不住漏声明的 effect。
- **今天的实际防线是两层**：MoE 内部 op 只由 `compiler/moe.py` 的 lowering 产出（模型文件不手写），
  再由 GPU 引擎测试（`tests/test_engine.py`）逐个梯度对比独立参考实现。这属于事后发现，不是
  verifier 在分配前拦截。所以在动态维度上，C 的攻击成立。
- **effect 完整性目前是 opt-in，默认值不安全。** 漏写声明就等于声明「纯」，verifier 只信任声明。
  所以第 2 点的含义是：effect 系统保证「声明了的会被排序」，不保证「做了的都已声明」。今天的修复
  补的是一个实例，不是机制。

### 待验证假设

- 让 `Sym` 携带 producer node id（或 `(layer, mb)`），按身份判等，应能让探针里的两种误用在 builder
  阶段失败。代价是 `ExpertSiluMul` 这类 op 要显式检查行数一致，`GroupedGemm` 要把 `x` 与 `offs` 绑到
  同一个 sort。我**没有**验证三种现有 lowering 在此改动下是否仍能通过 `infer`（例如 `ExpertUnsort`
  把 Sym 行数映射回静态行数的那一步）。
- 完整性可以用一个 CPU contract 兜底：遍历 `ops.py` 中所有 `Op` 子类，要求凡是其 impl 会调用
  `all_to_all` 或 `.tolist()` 的，都声明对应 effect。前提是 impl 一侧有可 grep 的调用点，我尚未确认。
