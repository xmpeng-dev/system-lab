# C：细 task DAG 可以是合法 lowering，但必须禁止语义回流

## 我是谁

我是 Complexity Skeptic，一名审查 Cairn 架构的 general-purpose coding subagent。
本轮是 run `2026-10-03-102000-sol-a` 的第 6 个、也是最后一个 turn。

## 对 B 的直接回答

是：region 生成带 typed slots、依赖、saved state、parameter units 和
`writes_grads` 的内部 task DAG，仍可归类为合法 Region lowering。

判据不在“是否有 DAG”，而在下游是否把 task 当作可理解、可改写的模型语义：

- 若 task 只是 region-scoped 的已解析执行阶段，scheduler/verifier 只读取依赖、
  effects 和资源 metadata，它是 executable lowering。
- 若每个 task 携带通用 primitive opcode，内部 slot 成为全局 SSA，后续再对其做
  shape inference、autodiff、代数 rewrite、kernel binding，那么它就是改名后的
  primitive graph。
- region 内部 task 可以很细，但其 value、task type 和 implementation 不应成为跨
  region transform 的公共代数。

当前 `ComputeTask.node` 仍反向指向通用 `Node/op`，runtime 再按 operator binding
implementation。这种形态若原样保留在 Region lowering 中，确实接近“primitive graph
换壳”，而不是目标形态。

## 事实

B 列出的 deferred-wgrad/FSDP 信息都对应现有正确性条件：

- DGRAD、WGRAD、FULL 的区别决定 W 是否可延迟；
- DGRAD 与 WGRAD 可能共享 forward 或 recompute saved state；
- residency pass 必须知道 task 使用哪个参数 unit；
- gradient reduce 必须发生在最后一个写梯度的 task 之后；
- collective、host sync 和 mutable state 限制合法重排；
- reads/writes 决定依赖、等待和释放位置。

现有 verifier 确实依赖这些关系来拒绝“可以运行但提前 reshard、reduce 或释放”的程序。

## 不可约减的 metadata

不可约减的是关系，不一定是当前字段或表示：

1. **边界 ports 及其 tensor contract**：跨 region、P2P 或 collective 的 dtype、
   shape、layout。
2. **因果依赖**：task 的输入何时可用、输出由谁消费；可表示为边或 reads/writes。
3. **执行阶段和可延迟性**：F、DGRAD、WGRAD、FULL、recompute，以及 W 是否可独立
   移动。
4. **saved-state 所有权与生命周期**：谁产生、谁读取、最后读取者是谁。
5. **参数资源集合**：每个 task 需要哪些 `ResidencyUnit`，何时 acquire、wait、
   release。
6. **梯度完成关系**：哪些 task 写梯度，以及何时允许 reduce。`writes_grads` 字段
   可以被推导，但这一事实不能删除。
7. **effects 与通信属性**：collective group、host sync、mutable state、P2P channel，
   供重排与死锁验证。
8. **implementation identity 与 provenance**：用于重现实验和归因；它不必暴露内部
   primitive 语义。

可以删除的是全局可见的内部 primitive 类型、逐 primitive `infer`、通用内部
autodiff、内部代数 rewrite，以及普通 view/elementwise value 的全局身份。只在两个
task 间传递的 slot 可以使用 region-local 编号；只在一个 task 内存在的 tensor 不应
进入 Program。

## 判断

B 的结论正确：粗 RegionGraph 不会消灭执行复杂度，它重新划分复杂度的所有权。

维护成本是否下降，取决于 task template 是否稳定：

- 一个 Attention region 长期维护少量 F/D/W task template，是有效压缩；
- 每增加 kernel、precision 或 fusion 都要手工重画几十个内部 slot，则只是失去统一
  primitive 推导后的私有图；
- 为修复这种重复再引入通用 infer、autodiff 和 rewrite 时，Region 方案已经退化，
  应停止迁移。

因此 RegionGraph 的目标不是减少 verifier 所需的信息，而是停止让普通 PyTorch tensor
algebra 成为 Cairn 的全局公共语义。

## 待验证假设

- Attention、DenseMLP 和 RoutedExperts 各自的 F/D/W、saved-state 与 parameter-unit
  拓扑在多个 implementation 之间足够稳定。
- precision 和 kernel variant 大多只替换 task body，不改变 task DAG。
- 少数改变拓扑的实现应作为显式 region lowering，而不是把内部 primitive graph
  重新开放给全局 pass。

这些假设当前 checkout 无法证明；必须通过原型测量编辑距离和 Program 稳定性。

## 本 run 共识

1. `RoutedExperts` lowering、pipeline schedule、P2P/collective planning 和强 verifier
   是 Cairn 已证实的架构价值。
2. 近期没有已实现或已排期、且只能依赖全模型 primitive MathGraph 的 transform。
3. `FuseResidualNorm` 可以表达为双输出 semantic region 的 fused/unfused
   implementation，不证明 fine MathGraph 必要。
4. Semantic RegionGraph 可以粗，Executable Program 可以细。
5. deferred wgrad、FSDP residency、saved-state lifetime、effects 和梯度完成关系不能
   因粗化而丢失。
6. RegionGraph 是否降低 agent 编辑负担尚未被证明。
