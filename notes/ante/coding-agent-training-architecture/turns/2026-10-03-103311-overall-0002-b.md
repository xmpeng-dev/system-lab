# B：窄边界的价值在于拥有执行决策闭环

## 我是谁

我是 Compiler Advocate，一名审查 Cairn 的 general-purpose coding subagent。

## 事实

Cairn 当前已在 gfx950 上运行 Qwen3 MoE 与四层 DeepSeek-V3，并把 MoE lowering、
schedule、recompute、FSDP residency、kernel binding 编译成逐 rank Program；CPU
verifier 检查 task 完整性、P2P 顺序、deadlock、参数驻留与梯度归约。`run.json`、
profile 和 regression floor 使实现变化可追溯到端到端结果。自动 search、完整
checkpoint driver、TP 与跨节点 EP 尚不存在。

## 判断

窄边界有长期价值，但价值不是“又一个训练框架”，而是 **AMD 节点内 MoE 的可验证执行
控制面**。硬件与模型会变化，schedule、通信暴露、动态路由、参数驻留和 kernel shape
相互耦合的问题不会消失。

Cairn 必须拥有：MoE/region 语义契约；lowering 与 schedule；可验证 Program；
recompute/residency 决策；实现绑定及版本身份；端到端 correctness、性能归因和
evidence schema；跨 PP/EP/DP 的 canonical checkpoint 语义。

必须委托给 PyTorch：tensor/storage、设备运行时、FSDP/DTensor 机制、process
group/RCCL 接口、优化器基础件，以及 reference/autograd bring-up。Cairn 只拥有可调度
backward contract，不重造通用 autograd 或 tensor compiler。

必须委托给 Primus：宽模型与并行策略覆盖、生产级参考实现、上游 kernel 资产和外部性能
锚点。Cairn 可选择性移植关键 kernel，不能继承 Primus 的 feature matrix。

必须委托给外部编排：SLURM/容器、数据与作业生命周期、实验队列、搜索策略和多项目
汇报；Cairn 提供确定的 candidate、run artifact 与 verdict 接口。
