## 发言

### 事实

1. **引擎测试只覆盖 4 层、1 步，不经过 optimizer。**
   - `tests/test_engine.py:87,115`：两个模型都是 `num_hidden_layers=4`；全程只有一次 `runtime.step`
     （`:324`）。比较 loss（`LOSS_TOL=1e-3`，`:61,340`）和每个参数梯度的归一化平方误差（`:72`）。
   - `tests/test_pipeline_parallel.py`：默认 8 层（`:83`），同样只跑一次 `runtime.step`（`:182`），比较
     loss 和每个梯度。
2. **多步测试只有三个，各测一个窄性质。**
   - `test_learning.py`：150 步 AdamW，4 层，Markov 链数据。断言第一步 loss > 0.9·log V，且 150 步内
     收敛掉至少 50% 的可学习差距（`:45-53,183-190`）。每步都 reset `LoadBalanceTracker`（`:167`）。
     **它不跑 Muon**，而 Qwen3 的 shipped config 用的正是 Muon。
   - `test_normalization.py`：比较多种 (dp, ep) 切分下的梯度缩放是否一致。
   - `test_weight_staleness.py`：2 rank，验证 FSDP2 的两个前提。
3. **contract tier 规模**：19 个文件、230 个测试函数，参数化展开后 C 统计为 848 个 case。主体是
   `test_profile`（39 个函数）、`test_compiler`（29）、`test_record`（23）、`test_regression_matrix`
   （16）、`test_recipes`（15）。kernel 层有 11 个文件，逐 op 对照 torch reference。
4. **`bench/check_regression.py` 完全不检查 loss**（全文 `grep -i loss` 为 0）。AGENTS.md 里
   「loss 4.727 对 4.726」这类对比是人工做的，没有工具守护。

### 判断

**攻击 1 成立。** 多步之后才显现的错误，目前只有一张很粗的网：`test_learning` 能发现「完全不学」，
发现不了「学得稍差」。具体缺口：

- Muon 的状态、gradient accumulation 的跨步正确性：没有测试；
- FSDP 跨步 reshard：只在 2 rank 下验证了「weight 对象不变」这个前提，没有验证数值；
- load-balance 的跨步计数：只在 `test_learning` 里被执行到，没有断言。

**攻击 2 成立。** 端到端 loss 曲线没有自动守护者；`regression.toml` 只守吞吐。

**攻击 3：逐条核对缺陷，结果对我方不利。**

**8 个缺陷，0 个由事先存在的测试发现；4 个发现后补了测试；4 个至今无测试。** 现有体系是一个
「棘轮」：已知性质一旦写成测试就不会退化，但它不会主动发现新一类错误。结构性原因：8 个里有 6 个
属于「声明、记录或 verifier 本身不完整」，这类缺陷的定义就是不改变梯度，所以最强的「逐梯度比较」
对它们天然无效。

**我仍坚持的部分**：对「改错数学」这一类——VJP 写错、seam 接反、梯度路径漏掉、residency 窗口
错位——引擎测试和 pipeline 测试配上独立的 plain-torch reference，加上 verifier 的 96 个调度 case，是
一张强且可复现的网。而这正是 coding agent 改 pass 或 lowering 时最常犯的错误。

### 待验证假设

- 补三类 CPU contract，预计能覆盖表中 4 个至今无测试的缺陷（未做原型）：
  - 「声明 vs 实现」：遍历所有 `Op`，检查 impl 调用的 collective / host read 与声明的 effects 一致；
  - 「记录 vs 实际」：bindings 按 node 比较；
  - 「digest 敏感性」：对每个 task 字段做变异，digest 必须随之改变。
- 多步 reference 对比可以覆盖攻击 1：同一个 4 层模型、同一 seed，跑 N 步 Muon，比较参数轨迹。
  plain-torch reference 已能按名读取参数，看起来可以扩展；但 Muon 的分布式 gather/broadcast 能否在
  reference 侧复现，我没有确认。
