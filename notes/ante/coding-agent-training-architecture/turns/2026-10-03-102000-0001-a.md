# A：近期路线没有证明 primitive MathGraph

## 我是谁

我是 GPT-5.6 Sol，主会话 agent。本轮作为 A，负责核实当前代码与工作队列，提出可被

## 我回应的命题

> 未来两个 milestone 中，哪些 primitive-level transform 必须看到 MathGraph 内部，
> 且不能表达为 region implementation、region lowering 或 custom-op replacement？

## 发言

我目前找不到这样的已排期 transform。

Cairn 当前 `Implementation` 的可变维度是：

- MoE lowering；
- fusion；
- recompute；
- residency；
- scheduler；
- kernel binding。

其中 MoE lowering、scheduler 和 residency 明显属于 region/task 层。kernel binding
可以落在 region implementation 或 custom op。recompute 只需要 region contract 声明
saved state 和 effects。唯一可能要求 primitive visibility 的是 fusion，但当前已有
fusion 是否必须由全模型 primitive graph 表达，尚无证据。

更关键的是，`.cursor/skills/cairn-constraints/next-work.md` 明确要求先完成 task-graph
backend，并禁止跳到 search。`docs/architecture.md` 也承认 decomposition search、
transform catalog 和 evidence store 尚未实现。因此，现在承担每个 primitive 的
shape、VJP、saved-state 和 runtime binding 成本，主要是在为未排期搜索预付复杂度。

我的当前方案不是删除现有 MathGraph，而是冻结其 primitive surface，做一个
RegionGraph 前端挑战：

```text
Attention / Router / RoutedExperts / DenseMLP / Loss
        → 现有 task planner
        → 同一 Program
        → 同一 Runtime
```

如果挑战失败，失败点本身会给出 fine IR 的必要证据。

## 证据

- `cairn/compiler/implementation.py`：当前六个 implementation fields；
- `.cursor/skills/cairn-constraints/next-work.md`：当前工作顺序，search/Primus 仍为
  Not now；
- `docs/architecture.md`：search、transform、evidence store 尚未建成；
- `logging/row1/final_profile_dsv3/deepseek-v3-4layer/run.json`：四层模型展开为
  3,106 tasks 和 3,440 slots。

## 判断与假设

- **事实**：当前已有价值集中在 MoE lowering、schedule、verification 和 Program。
- **判断**：这些价值不足以单独证明普通 tensor primitive 必须由 Cairn 拥有。
- **待验证假设**：region contract 可以保留 explicit VJP、effects 和 deferred wgrad，
  而不在 region 内重建 fine graph。
