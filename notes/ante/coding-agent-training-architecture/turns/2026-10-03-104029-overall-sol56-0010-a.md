# A：Compiler 产出完全绑定的 ExecutablePlan

## 阶段

```text
1 ResolvePolicy
  config + hardware → immutable CompilePolicy
2 SemanticRewrite
  RegionGroup / lowering / fusion selection
3 LayoutSolve
  finite RegionEdge domains → chosen layouts + conversions
4 TaskLowering
  regions → typed F/D/W/collective task templates
5 ExecutionPlanning
  micro-batch expansion → schedule → residency → memory lifetime
6 Bind
  task → concrete executable identity + version + arguments
7 Verify
  single-rank + cross-rank Program checks
```

最终对象应称为 `ExecutablePlan`，包含：

- fully ordered tasks；
- concrete executable reference 与稳定 identity；
- slots/saved-state/resources/channels；
- waits/effects/frees；
- environment requirements；
- complete provenance 和 digest。

Runtime 不再读取 `Implementation`，不按 operator type 选择 kernel，也不推导 peer、
layout、residency 或 overlap。它只：

1. 将 plan 的逻辑 device/group/resource handle 连接到本进程环境；
2. 在执行时解析 FSDP 当前 materialized parameter tensor；
3. 顺序调用已绑定 executable；
4. 收集 measurement。

live parameter resolution 是执行环境适配，不是性能决策。Python callable 可以在 setup
时由 bound executable descriptor 实例化，但 descriptor 已由 compiler 决定。

## 当前需要收敛之处

当前 `Program` task 仍携带 `Node/op`，Runtime 通过
`implementation.kernels.for_op(op)` 绑定 implementation；compiler 又依赖
`runtime.impls.AutogradVjp`。应倒置依赖：

```text
compiler owns executable protocol/descriptor
runtime implementations implement protocol
plan carries bound descriptor
executor consumes plan
```
