### 分歧 1：effect 对照不需要 GPU，应列为一项低成本的 CPU contract

C 的表在第 2 层写的是「effect 声明与实际对照（**GPU**）」，我不同意这个成本定性。

- **事实**：树里所有发起 collective 或 host 读的调用点只有 7 处，集中在 3 个文件：
  `runtime/impls.py:454,649`、`ops/all_to_all.py:62,84`、`ops/ep_dispatch.py:100,171,174`。其中
  `impls.py:649` 恰好在 `FusedRoutedExpertsImpl` 里——它**不是** `CollectiveImpl`，却直接调用了
  `dist.all_to_all_single`。turn 3、9 讨论的漏声明正是这种结构造成的。
- **判断**：可以写一个基于 AST / 调用图的 CPU contract——凡是能（传递地）到达 `dist.*` 或
  `.tolist()` 的 impl，它在 `KernelBinding.for_op` 中绑定的 op 的 `effects()` / `backward_effects()` 必须
  声明对应的 `Collective` / `HostSync`。`Impl.host_syncs`（`impls.py:100`）已经是按 body 计数的声明，
  可用于交叉核对。
- **影响**：成本从「需要 GPU 的实验」降为「CPU contract tier」。它仍在第 2 层，但任何 agent 都能在
  没有 GPU 的情况下完成。
- **待验证**：impl 调用的 Triton / FlyDSL kernel 内部是否同步 host，静态分析看不到，仍需 GPU trace
  验证。

1. **它是唯一一项「不做就可能永久丢失」的工作。** `git status --untracked-files=all` 显示这几个目录加
