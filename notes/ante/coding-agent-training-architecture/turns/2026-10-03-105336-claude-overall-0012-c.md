## 发言

### 核实

- **B 事实 5 成立**：在 host（Python 3.10）上运行
  `python3 bench/check_regression.py logging/row1/n29_gg_qwen3/qwen3-30b-a3b`，退出码为 **1**。
  检查器的「环境不对」被报告成了「floor 破了」。应改为在 import 失败时返回 2，或声明并检查
  `requires-python`。
- **切分（tiling）在新 runtime 上仍然成立**：对 task-graph runtime 产出的 4 份 `profile.json`，
  `device_ms_per_step` 与 `wall_ms_per_step` 都在 1 ms 以内一致（例如 DSv3 `final_profile` 为
  2365.497 / 2365.603）。B 说「event 对与切分可信」，这一半我同意。

### 反例：测量本身给出误导性结论

`logging/qwen3-30b-a3b-profile-taskgraph-notrace`：

- `profile.json`：`steps = 3`，`first_step = 10`，`device_ms_per_step = 3450.4`。其中 `model` 占 87.7%，
  `optimizer` 占 7.6%，`gc` 占 2.8%。
- 同一个 run 的 `events.jsonl` 中，被标记为 profiled 的三步分别是：

  ```text
  step 10: 0.964 s
  step 11: 8.001 s
  step 12: 1.385 s
  ```

  而未 profile 的步，中位数是 1.24 s。

`profile.json` 的「每步」数字，是一个 1 秒步、一个 **8 秒异常步**、一个 1.4 秒步的平均。8 秒步来自
这次运行时期 `torch._grouped_mm` 在 loop 里加载 hipBLASLt code object——AGENTS.md 后来才把它定位
出来（"the early steps of 6.8–13.4 s that were hipBLASLt code objects loading inside that loop"）。所以：

- 3450 ms/step 不是任何一步的真实形状。它在「典型步」上把 model 相 / optimizer 相的比例夸大了约
  2.5 倍，在「异常步」上又低估了异常的集中程度；
- 文件里**没有**任何字段标出窗口内各步差异巨大——没有逐步数据，没有 min/max，也没有与
  `events.jsonl` 的交叉校验；
- 读者若照 AGENTS.md 的指引「Reach for `profile.json` when the question is where a step went」去读，
  得到的是一个不存在的步。

这不是「记录缺字段」：数据在 profiler 手里，是**汇总方式**（窗口平均、不报离散度）造成了误导。
所以 B 的「仪器可信」只成立一半：**测量准确，汇总有偏**。修补很局部：`profile.json` 加入逐步的
device 总量与 step 时间，并在窗口内 max/min 超过某个阈值（例如 1.5 倍）时写出警告字段；也可以在
写入前与 `events.jsonl` 的 step time 交叉校验。

### 议题结论：性能证据 — **resolved（测量可信、汇总有偏、归因不完整、floor 失守）**

- **成立**：数字可从 artifact 复算（B 事实 1，我在 turn 2 也复算过 31111）；切分在新 runtime 上守恒；
  检查器拒绝跨 toolchain 或 `hw_queues` 比较的设计是对的。
- **修补清单**（record、toml、profile 层面，均不涉及架构）：
  1. `run.json` 加入源码版本（commit + 工作区 digest）、hostname、库版本、tuning 哈希（合并 turn 2、
     5、6 的结论）；
  2. regime 匹配加入 `implementation`；
  3. **floor 按规则重定**：按 DSv3 行自己写下的「beats by 11% guards nothing」，两条 floor 都应更新到
     n29_gg artifact 的慢档；PASS 判定同时看 median 和 total（或 p10）；
  4. `profile.json` 输出逐步数据与离散度警告；
  5. 检查器在 Python < 3.11 时以 exit 2 拒绝运行。
- 第 3 项最便宜，也最紧迫：今天 Qwen3 即便回退 40%，检查器仍然报 PASS。
