# B：粗语义图可以成立，但 lowering 不是轻量 contract

## 我是谁

我是 Compiler Advocate，一名审查 Cairn 的 general-purpose coding subagent。本轮回应
A 关于“细 Program、粗 Semantic Graph”的分层。

## 我回应的命题

我基本捍卫 A 的分层，但反对把 region lowering 描述成简单接口适配。以
**deferred wgrad 与 FSDP residency 的组合**为例，它必须生成细粒度执行模板。

## 事实

当前机制分三步：

1. `autodiff.py` 根据每个 primitive node 的参数输入和 kernel binding，将 backward
   拆为 `DGRAD`、可延迟的 `WGRAD` 或不可拆的 `FULL`。
2. `exec.py` 在 `defer_w=True` 时从 B lane 删除 `WGRAD`，稍后在独立 W lane 恢复；
   DGRAD 和 WGRAD 仍共享 forward/recompute 保存的 state。
3. `residency.py` 扫描排好序的 tasks，通过每个 task 的 `units` 和
   `writes_grads` 插入 acquire、wait、release 与 grad-release。memory pass 再以
   B/W task 对 saved state 的最后一次读取决定释放位置。

因此 Region lowering 至少必须产出：

- F、DGRAD、WGRAD/FULL 的 task 身份及依赖边；
- 哪些 WGRAD 可独立延迟，哪些 backward 必须保持 fused；
- 每个 task 读取、写入的 slots；
- DGRAD/WGRAD 共享的 saved state，以及 recompute 后由谁最后读取；
- 每个 task 使用的参数集合及其 `ResidencyUnit`；
- 哪个 task 写参数梯度，梯度何时才允许 reduce；
- task 的 effects/collective 属性，供 verifier 检查重排合法性。

少一项都可能产生“能运行但梯度提前 reduce、参数提前 reshard 或 saved state 提前释放”
的错误。

## 判断

这些信息是一个**细粒度执行 DAG/task template**，但尚不等价于 primitive semantic
graph。

区别在于：task template 不需要为内部 `Linear`、`Reshape`、`Add` 提供通用语义、
shape inference 和可跨 region 重写的代数；它只需由特定 region lowering 生成已解析的
任务、依赖和资源 metadata。后续 scheduler、residency 与 verifier 操作 tasks，而非
重新理解模型 primitive。

但是，粗 RegionGraph 并没有消灭复杂度：它把当前 autodiff 从 primitive graph 自动推导
的信息，转移成每个 region lowering 必须正确声明的责任。A 的架构分层成立，其维护
成本优势尚未成立。

## 待验证假设

如果 Attention、DenseMLP 和 RoutedExperts 的 task templates 稳定，且少量共享 helper
足以表达，上述转移会降低 agent 的语义编辑距离。

如果每次新增 fusion、precision 或 kernel backward 都要同步修改 region 内部 slots、
saved state、参数使用和 WGRAD 拆分，那么 region lowering 会演化成没有统一 verifier
的私有 primitive graph，A 的方案即被证伪。
