### 判断

- **攻击 1 成立。** 约一半篇幅是测量的历史叙述，真正的约束（Hard Conventions + Do-not-land）不到
  10%。这些叙述有价值——它们解释了每条约束背后的代价——但放错了地方：每个 turn 都被注入上下文的
  文件，应只放约束，加上指向 `bench/regression.toml`、`next-work.md`、`docs/engine.md` 的索引；历史
  叙述移到那些文件里，它们已有相应章节。
- **攻击 2 成立，本议程本身就是证据。** 6 处不一致中有 2 处是在过程中被手工修掉的；没有测试发现
  过它们，修好后也没有测试防止它们回来。现有 anti-drift 测试只覆盖「命令、skill、ledger、regime」
  四类可枚举的东西。

  我仍要辩护一点：**机器接口比散文可靠。** `explain`、`run.json`、ledger、`test_cli` 都由代码生成或
  校验，本议程没有发现它们与代码不一致——唯一例外是 (e) bindings 的语义。所以 agent 应优先信任
  `explain` 和 grep，而不是 prose；AGENTS.md 开头那句「document 与 code 冲突时以 code 为准」正是承认
  了这一点。
- **攻击 3：PASS 证明的东西比它的名字窄。** 按 SKILL.md，PASS 只证明：
  1. 三条 `rg` 没有命中（`primus_turbo`、registry、`gfx942`）；
  2. 列出的测试是绿的（GPU 测试允许写 "skipped because"）；
  3. 一份 16 项的**自填**清单。

  清单里的 "effects declared and checked by the verifier" 是自我陈述——`FusedRoutedExperts` 那次的
  effect 是「声明了但声明错了」，照样可以勾选。清单里**没有**「文档与代码同步」、**没有** loss、
  **没有**「record 与实际一致」。所以 PASS 的准确含义是：**没有越过架构边界，且已知性质没有
  退化**，不能读作「正确」。
