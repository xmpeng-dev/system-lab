# A：把 coverage 当成有预算的产品状态

## 提案

每个可运行配置都必须输出三种状态之一：

```text
structural-only  # CPU compiler/verifier 通过
correctness      # loss + 全 gradients 通过 GPU reference
protected        # correctness + E2E regression floor
```

### Admission

一个 regime 只有同时满足以下条件才进入 `protected`：

1. 对应 shipped config 或当前 roadmap 的一个真实决策；
2. 环境、mesh、batch、precision 和 Implementation 可完整记录；
3. 至少两次稳定基线，方差足以设 floor；
4. 有明确 owner 和失败处理路径；
5. 它增加新的 failure surface，而不是复制已有 bucket。

### Expiry 与 eviction

- hardware、ROCm/PyTorch、关键 kernel backend 或 regime identity 变化后立即 `stale`，
  不把旧 floor 判为通过；
- shipped config 删除、连续两个 milestone 无 owner，或被另一 regime 完全覆盖时
  eviction；历史 measurement 保留；
- `stale` 只能通过重测恢复，不能人工改版本字段。

### 硬预算

- 每个模型最多 **2 个 protected regimes**：最小正确性/低 batch 和目标吞吐 regime；
- 每增加一种 precision，最多新增 **1 个跨模型代表 regime**，不做模型笛卡尔积；
- 每个 PR 的强制 E2E 不超过 **2 个 regime**；其余按改动影响矩阵选择；
- 全 protected set 每周完整跑一次，目标总 GPU 成本不超过 **16 node-hours**；
- 超预算前必须 eviction 或证明新增 failure surface。

correctness 不采用相同硬上限：CPU contracts 全量跑，GPU reference 按模型/region
contract 参数化，但使用小 shape。

## 未保护标记

`cairn explain` 和 `run.json` 必须显示：

```text
coverage:
  structural: pass
  correctness: matched | unmatched | stale
  performance: protected | unprotected | stale
  nearest_regime: ...
```

不允许把 `unprotected` 显示为 pass。
