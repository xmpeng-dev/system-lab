# B：Roadmap 必须由真实性能任务牵引

## 顺序修正

1. Policy 显式化应早于 descriptor/Region，否则会把隐式常量固化进新架构。
2. 先测 `interleaved`/`DualPipeV` 的 `pp>1` E2E；不能用大量 snapshot 冻结未经测量的
   偶然实现。
3. 一个 Attention slice 不足以进入全量迁移；至少需要 dense region 与
   `RoutedExperts` 两个相反 vertical slices。

## Gate 修正

- snapshot 比较 semantic outputs/effects/resource lifetime/fault classes，不锁 task ID；
- descriptor 只做 slice 所需最小 seam；
- 双前端限时一个 milestone、最多两个 regions；
- 两个 slice 都完成真实变换：attention implementation replacement 与 MoE
  lowering/overlap；
- Edit-to-Verdict、first-pass correctness 或定位时间必须改善，才能进入迁移；
- 旧路径经一个稳定 milestone 后删除；
- search 前先用 action/observation schema 完成三次人工 transform。

artifact 只服务 gate/query，不能复制 `run.json`。Candidate 只用于性能实验。rollback
必须记录 source revision、kernel identity、container/toolchain 和 base plan。

修正路线：

```text
测量现有 schedules
→ 最小 Policy 显式化
→ 最小 descriptor seam
→ dense + MoE 双 slice
→ Owner go/no-go
→ 分区迁移
→ 三次人工 transform
→ 外部 search
```

每个阶段必须服务 `next-work.md` 的真实性能问题；若只增加 artifact 而不缩短
Action→Verdict，立即停止。
