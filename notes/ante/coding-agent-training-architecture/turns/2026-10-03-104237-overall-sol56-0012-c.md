# C：Runtime 应无策略，而非无条件分支

`KernelDispatchRef` 动态查表不是隐藏决策，只要它是 compiler 已绑定的有限决策函数。
允许的 late binding 包括 group/tensor/buffer 物化、声明 peer 连接、唯一 shape-table
lookup 和已选 variant 的 lazy code materialization。

动态 dispatch 必须满足：

1. table、bucket 函数和 artifact hash 进入 Plan/Manifest；
2. executable 在 setup 已绑定；
3. lookup 唯一、确定且覆盖声明 domain；
4. miss/歧义/capability 不符立即失败或重新编译；
5. 不测量、不学习、不修改表；
6. 实际命中 row 进入 run record。

禁止在线 autotune、heuristic、silent fallback，以及改变 precision/layout/group/schedule/
residency/stream policy。

## 本议题结论

Compiler 产出 symbolically complete Plan；setup 只物化环境和 BindingManifest；Executor
只求值已绑定条件、执行和测量。当前 Runtime 按 operator type 读取 kernel binding 的
路径应移出。
