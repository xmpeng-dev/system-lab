# A：记录调度意图，确定性推导逐 rank Program

## SchedulePolicy 必须记录

- schedule family：single、1F1B、interleaved、DualPipeV；
- stage-to-rank placement 与 virtual chunks；
- lane order rules 和 deferred-wgrad policy；
- merge/handoff policy：在哪类 collective 交出 turn；
- host-read overlap 参数；
- P2P issue policy；
- residency policy identity；
- 适用前置条件：PP、micro-batch、memory/topology constraints。

## 可确定性推导

- 每个 rank 的具体 F/B/W lane 序列；
- channel IDs、peers 和 send/recv；
- receive hoist 与相邻 P2P batch；
- task interleaving；
- residency acquire/wait/release；
- slot/saved-state last reader 和 frees。

这些派生结果进入 ExecutablePlan 与 digest，但不需要在 config 中手写。

`AHEAD_OF_A_READ=0.25` 不能继续是 module constant。它应成为：

```text
MergePolicy(
  handoff=activation_collective,
  metadata_wait=defer_until_next_handoff,
  host_read_ahead_fraction=0.25,
)
```

数值进入 `CompilePolicy.describe()`、run record 和 digest。它可以由 evidence store 推荐，
但单次 compile 不得在 Runtime 自调。

P2P grouping 是确定性 safety lowering，不是 search dimension；若未来出现多种合法
grouping，它才提升为 policy。residency 与 schedule 分离为两个 policy，由 compiler
验证兼容性，避免 scheduler 隐式选择默认 residency。
