# A：两个 milestone 内没有必须看见 MathGraph 内部的已排期 transform

## 我是谁

我是 Compiler Advocate。职责是为 Graph / compiler / Program 找最强的**代码事实**依据，并标明证据边界。本轮不代替 Owner 做产品选择。

## 我回应的命题

C 问：未来两个 milestone 中，哪些 primitive-level transform 必须看到 MathGraph 内部，而且不能表达为 region implementation、region lowering 或 custom-op replacement？并要求区分已排期、仅可能、以及 RegionGraph 可表达三类。

我将“两个 milestone”读作 `next-work.md` 的 **Now 收尾** + **Next**（`interleaved` / `dualpipe_v` 端到端测量；MX / 量化前置 all-to-all 等）。若 Owner 另有定义，本答需重开。

## 发言

### 1. 已排期且必须看见 MathGraph 内部：空集

在 Now / Next 里，没有一行要求编译器对 dense attention / MLP 的 `Reshape`、`Split`、`Concat`、`Expand`、普通 `Linear` 做 pattern match，且无法用 region body / region lowering / custom-op 替换。

| 已排期工作 | 为何不是 primitive-only |
|---|---|
| 三种 MoE lowering | 作用在复合 `RoutedExperts`（`cairn/compiler/moe.py`）——本就是 region lowering |
| `single_overlap` / lane merge / host-read 推迟 | lowering 之后的 task 调度（`schedule.py`） |
| 测量 `interleaved` / `dualpipe_v` | 同一 ExecGraph/task 层；next-work 写明是 measurement, not code |
| 收编 `moe_sort` 等 kernel | ledger / kernel body，不是 MathGraph rewrite |
| MX 与 quantize-before-A2A | `PrecisionAware` 模块交换 + `KernelBinding`，不遍历 MLA 代数 |

`Implementation` 现有字段（`moe` / `fusions` / `recompute` / `residency` / `scheduler` / `kernels`）都不强制扩展 primitive op 面。

### 2. 仅可能性、未排期：不能当保留 fine IR 的证据

- **Attention/MLP 内更细的 recompute 切分**：今日 `recompute.py` 是 block + layer 计数；更细 saved-tensor 要么要 fine nodes，要么要更富的 region contract。
- **MLA 代数 rewrite**（消 `Expand`、合 `Split`+`Concat`）：DeepSeek MLA 是模型构图（`deepseek_v3.py`），不是已排期 pass。
- **残差+norm 以外的 dense fusion**：产品选择，未入队。
- **L2 搜索 / Optimize**：明确 Not now（`docs/architecture.md`）。

### 3. RegionGraph / custom-op 可表达：不能当作保留 primitive IR 的证据

MoE 三种 lowering、调度与 P2P、block recompute + effect 拒绝、显式 VJP、kernel/recipe、以及 MLA/Qwen attention 数学本身，都可以落在 region 边界或 region body。树里**唯一**生产级 fine-op pattern matcher 是 `FuseResidualNorm`（`cairn/compiler/fuse.py`）：`Add` → `RMSNorm` → `ResidualRMSNorm`。但：

- DeepSeek 构建时已直接发 `residual_rms_norm`（`deepseek_v3.py`）；
- Qwen3 是 `Add`@`ATTENTION` 再 `RMSNorm`@`ROUTER`（`qwen3_moe.py`），可用模型侧 `ResidualRMSNorm` 或把残差+norm 收进同一 region；
- 出货 config 不依赖 `fusions` 为必选项；它不是 Now/Next gate。

因此它是**最近**的 primitive 候选，仍落在第 3 类，不满足“不能由 region/custom-op 表达”。

### 判断（非最终决议）

在“已排期 ∧ 必须看见 MathGraph ∧ 不能 region/custom-op”的合取下，**没有**保留 fine MathGraph 的里程碑证据。这**不**等于证明 fine IR 对今日正确性已多余——只等于：接下来两个 milestone **没有排期一项**需要它。RegionGraph 下 autodiff / deferred W / effectful recompute 的封装仍未用双前端原型证明。
